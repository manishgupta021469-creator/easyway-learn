Easyway Learn v69 — Demo removal + persistent student/document data hardening

1. Removed all built-in demo/sample student accounts, demo textbook subjects, sample pages, sample Q&A/formula content and demo share requests.
2. Older browser data is migrated without deleting user-created content; only the known legacy demo records are removed.
3. New Student IDs start with an empty learning library. No demo content is injected after registration or login.
4. Student learning state is saved to the authenticated Student ID on the server, including subjects, books, chapters, pages, OCR/extracted text, paragraphs, progress, scores/history, shares and audit data.
5. Server state writes are atomic at the application-store level and the browser sync queue now re-runs after an edit arrives while a previous sync is still in progress, preventing stale writes from silently dropping later edits.
6. Server reads now restore the complete saved snapshot instead of selectively overwriting only non-empty arrays, so saved empty/non-empty fields remain consistent.
7. Uploaded page image/PDF assets continue to be stored in IndexedDB and uploaded to the authenticated server asset store; OCR text is stored in the learning state.
8. Empty new accounts have a proper first-use dashboard instead of relying on demo content.
9. OCR from v68 is retained: text PDFs use pdftotext first; scanned PDFs/images use Tesseract with English + Hindi support.

IMPORTANT DEPLOYMENT STORAGE NOTE
The application is configured to persist server data under EASYWAY_DATA_DIR. Render Free web services have an ephemeral filesystem, so SQLite/files uploaded to the service can be lost after a restart, spin-down or redeploy. For true server-side persistence on Render, use a Render Postgres datastore or attach a persistent disk to a paid web service and set EASYWAY_DATA_DIR to its mount path (for example /var/data).
